Executive orientation

One intent, one authority chain, one settlement

Converge is the factory coordinator and assurance layer around independent decomposition and task-contract engines. It sequences authority without duplicating it, binds one authorized task to a bounded runtime, and settles only after inspectable evidence. It is the referee, not the player.

9method passes
2phases, one barrier
0.2.0immutable release
508audited tracked paths

The coordinator

Converge owns cross-engine sequence, composition receipts, runtime binding, the bounded loop, and settlement. It does not own seam discovery, Task-Spec rendering, HMAC authorization, or acceptance internals.

The engines

Seamwise turns reviewed evidence into seams, swimlanes, capability legs, and a versioned TaskPlan with lineage. Task-Spec materializes atomic tasks, seals them under an HMAC key, runs evals, and performs independent acceptance.

The humans

A named reviewer accepts the adversarially reviewed topology and owns residual risk. A human key holder authorizes one exact task revision. Neither decision transfers to changed bytes.

The boundary

A reviewed topology is not a task. A materialized task is not authorized. A green eval is not acceptance. A local settlement is not a merge. Every chapter keeps those evidence layers separate.

The shortest useful mental model is: intent → reviewed topology → unsigned tasks → sealed revision → bound runtime → finite loop → independent acceptance → scoped settlement. Everything else exists to keep that chain honest.

Unease · duplicate authority

Agentic delivery fails when authority becomes ambient

The hard problem is not getting an agent to act. It is deciding who is allowed to decide what.

In a typical agentic stack, the planner decomposes, the coordinator schedules, the executor edits, and the observer reports — and each of them can quietly claim the others' verbs. A planner marks work approved. A coordinator dispatches what it merely drafted. An executor declares its own output done. An observer's dashboard becomes the team's memory of truth. Four layers, four overlapping claims of APPROVED.

When every layer can decompose, authorize, execute, and declare done, no receipt means what it says. The failure is not bad models; it is duplicated authority making every downstream artifact ambiguous.

Four flattenings to refuse

Model narration ≠ acceptance

A fluent summary of what was done is not an acceptance decision. Acceptance belongs to an independent gate applied to the exact handoff and revision.

Tracker state ≠ authority

An issue board is a projection. It authors no tasks, changes no dependency truth, and never overrides repository files.

Materialization ≠ dispatch

Writing an unsigned task set proves materialization integrity. It grants no permission to run anything.

Observation ≠ control

A UI that renders canonical state cannot create, approve, bind, transition, or settle it.

Converge's answer is to get thinner, not bigger. It removes duplicated authority instead of adding another layer that claims it.

Sources: brf-converge.md §5 S02; underlying docs/concepts/authority.md, docs/trust/index.md.

Unease · the category

It is a referee, not the player

Converge sequences independent engines and verifies boundaries. It does not absorb their authority. Seamwise and Task-Spec remain independently versioned binaries with their own capability contracts; Converge composes them across process boundaries through JSON and CLI bridges, with no shared implementation box.

Converge ownsConverge does not own
Cross-engine sequenceSeam discovery
Composition receiptsTask-Spec rendering
Runtime bindingHMAC authorization
Bounded loop + settlementIndependent acceptance internals

Everyday work and factory work are different planes

OPERATING.md assigns the everyday plane — portfolio triage, nuances, backlog — to WorkHelm. Converge is the dock, factory, and big-bang assurance plane: the route for work that must carry receipts. Neither lane may skip the Task-Spec HMAC seal, and neither merges the user's branch automatically.

Refusal. Converge is not the everyday portfolio coordinator, and it must never be presented as one. That plane belongs to WorkHelm by explicit operating contract.
Part 02 recap: the category is a thin coordinator. Converge exists because agentic delivery needs a referee that sequences authority, binds attempts, and refuses to settle without proof — not another player claiming the ball.

Descent · passes 0–1

Capture asks whether the idea should exist

Pass 0 · Capture (optional). Raw idea in; owner-voice BRD or durable no-go out. The interview asks every currently unblocked question together — the live frontier — waits once, and recomputes. It covers quantified pain, a KPI-shaped goal, in/out scope, provenance, owner, open questions, and canonical sign-off. Draft mode may explain gaps but never authorizes.

The do-nothing test is a kill switch. If inaction has no meaningful cost, the correct output is a durable, owned, dated, specific no-go — not a manufactured project. The fastest valid result can be an honest stop.

Pass 1 · Intent converts the brief into a technical contract

Client problem in; falsifiable tech-spec out. BRD claims pass through interrogate and crystallize gates into numbered requirements. Unsigned inputs, pending items, open blockers, invalid dates, and ambiguity fail closed.

PassInputOutputClosing gate
0Raw ideaBRD or no-goCHECK_BRD=PASS
1Signed BRDFalsifiable tech-specCHECK_TECH_SPEC=PASS
Altitude discipline. Intent stays above architecture: a tech-spec names observable behavior, constraints, and blockers — not infrastructure preferences disguised as requirements. Implementation leakage may warn; unresolved blockers still block.

Descent · passes 2–3

Structure names the terrain; Decompose cuts the seams

Pass 2 · Structure. Tech-spec plus the real repository in; grounding ADRs and a shared context glossary out. Final mode rejects proposed-only ADRs, dangling supersedes, empty evidence, and missing context. The key rule is what an ADR must not become: record what is true about the ground, and leave "build, create, implement, refactor, migrate" to the next pass.

Pass 3 · Decompose. ADRs in; one typed swimlane tree with capability legs out. The grammar has three nouns: a seam separates responsibility, a swimlane owns it, and a leg names an observable capability state. Plans with no seams, no non-goals, no legs, orphan legs, or missing proof all fail.

Altitude drift is a defect. A leg is not yet an atomic Task-Spec; real task IDs appearing in Pass 3 output mean the plan collapsed into a task list and must be redone.

A coherent plan is still only one model's story. Before topology can be accepted, an adversary has to attack it — that is Pass 4, and the barrier behind it deserves its own part.

Descent · pass 4

Consensus: a different-family model tries to break the plans

Refutation in. Hardened plans, an objection log, owners, decisions, and residual risk out.

Pass 4 sends the primary-family plans into a cross-family adversary chamber. Self-review, no objections, no named decider, and open residual risk all fail the gate. Dispatching the adversary does not close the pass: an objection exists until a human decides it — FIX or ACCEPT — via cvg review --resolve, owning the residual risk by name.

Scrutiny is not consensus. A fresh review log with unresolved findings is evidence of scrutiny, not agreement. Only a fully decided objection log reaches the barrier.

What crossing the barrier means

  • The topology, objection log, and residual-risk decisions are accepted as reviewed.
  • Passes 5–8 — machine build — may begin against exactly those bytes.
  • Any later mutation invalidates consent and re-routes to adversarial review.

What it does not mean

  • No task has been authorized. Materialization and sealing are separate, later acts.
  • No execution may begin. Reviewed topology is not dispatch authority.
  • No acceptance has occurred. Acceptance belongs to Task-Spec after execution.

Bounded motion · non-authorizing receipt

Materialize writes unsigned tasks — and the receipt says so

Task-Spec batches the reviewed plan into atomic leaves with runnable evals, dependency closure, scope, budgets, and acceptance criteria. Converge writes the composition receipt only after the exact task set exists; interrupted finalization recovers idempotently and an exact rerun is byte-identical.

ConvergeCompositionReceipt/v1 binds engine versions, source commit, lineage, plan digest, task IDs, and task digests — with "dispatch_authorized": false. A valid receipt proves materialization integrity, not permission to run or acceptance after running.

Creation never grants authority

Open one materialized leaf: both lifecycle booleans remain false — signed_off: false, accepted: false. Seamwise review and Converge materialization are upstream evidence; neither may flip the Task-Spec seal. cvg tasks plan previews proposed units without inventing work for a missing leg, and the compatibility door forwards the standalone TaskPlan unchanged.

The seal is a separate human act

taskspec gate --stamp sets signed_off: true only after validating the exact body digest under the repository key — TIER=1. HMAC is tamper evidence under a shared key: not identity, not secrecy, not isolation, not semantic truth.

Pass 6 · Register is opt-in. One signed Task-Spec becomes one tracker issue with blocked-by mirroring the DAG; repository files remain canonical. Registration is a parity contract — count, identity, edges, receipts, and landed history must agree (145/145 register rows) — and a repo-local queue may skip it entirely.

Bounded motion · adapters and isolation

Prevent and detect are different control classes

An adapter selects a declared runtime, closes stdin, filters environment, and reports what it can enforce. Codex may prevent some writes before the tool call; Claude and Kimi often detect violations postflight. The resolver manifest records the class — documentation may not upgrade detect to prevent.

Preflight shield. Where the runtime supports it, out-of-policy writes are refused before the tool call executes.
Postflight tripwire. Elsewhere, violations are detected by the whole-Git postflight and fail the attempt — detection is not prevention, and this book never blurs the two.

Worktree isolation sees committed state only

Attempts run away from the live tree by default. Commit the sealed task and execution profile before looping, or the isolated checkout cannot see them; committing the contract is not merging product work or opening a PR. One run gets one isolated checkout and a scratch branch while the human's working tree remains untouched. Settled landings clean the duplicate worktree; BLOCKED/STALLED/EXHAUSTED keep inspectable uncommitted work.

The last preflight

bind --check re-hashes task, profile, policy, evidence, and runtime capabilities without changing the repository — verified by a direct test that observes zero writes. Only then can Pass 8 spend a budget.

REFUTEDloop back to learn
Kernel order: checkpoint → attempt → tier 1 → path gate → tier 2 → acceptance → receipt. An unobtainable tier-2 verdict never becomes a pass: low-risk documented unavailability may proceed under policy; high-risk work stops.

Three budgets fail differently

Iterations, working time, and tokens are independent ceilings; a CLI flag may tighten but never raise the signed maximum. --resume continues accumulated working time, not wall time spent paused. A missing token budget is reported as unbounded, never guessed. The stagnation breaker lands STALLED after repeated ineffective attempts — an ineffective engine stops at three attempts rather than the declared fifteen.

Sources: brf-converge.md §5 S47–S53, §6.E; underlying skills/task-loop/scripts/loop-kernel.sh, docs/guides/bind-and-loop.md (57/57 loop rows).

Settlement · terminal states

Eight terminal states make failure operational

Success, no work, human dependency, stagnation, exhaustion, cancellation, and coordinator error never collapse into one status. Only three states exit zero.

Settlement · acceptance and receipts

Acceptance belongs to Task-Spec; settlement is a hash chain

A green tier-1 eval proves only the encoded claim on this host — it can be weak or gamed, which is why the whole-Git path policy runs beside it and higher-risk lanes add a different-family judge. Tier 2 sees intent, diff, and holdout criteria and returns UPHELD, REFUTED, or unavailable.

Holdout secrecy is a goal, not a shipped invariant. The judge is intended to own ## Holdout, but the current worker brief still points at the Task-Spec that contains it. Do not claim the worker could not read evaluator criteria.

Converge hands the exact revision and attempt back to Task-Spec; only ACCEPTED=1 closes acceptance. Converge does not set accepted: true itself; worker narration and the execution receipt are insufficient.

Field guide · the composed path

From recipe to materialized task set

Point Converge at the pinned engines, then walk the compose state machine. Each command lands at a named state; status re-hashes evidence and names the single safe next action.

export CVG_TASKSPEC_BIN=/absolute/path/to/task-spec/bin/taskspec
export CVG_SEAMWISE_BIN=/absolute/path/to/seamwise/bin/seamwise

cvg compose prepare --source recipe.yaml
cvg compose review --reviewer owner --reason "Topology and rollback accepted."
cvg compose preview
cvg compose materialize
cvg compose status
CheckpointWhat to verify before moving on
After prepareState is NEEDS_REVIEW; delivery plan and lineage exist; Task-Spec untouched
After reviewNamed reviewer and substantive reason recorded; compiler still locked
After previewRead-only proposed DAG matches the reviewed plan; no Markdown written
After materializeReceipt carries dispatch_authorized: false; leaves have both lifecycle booleans false

Field guide · authorize, bind, run, accept

One sealed revision, one bounded attempt

taskspec gate --stamp cvg/tasks/T-20260815-health-status.md
cvg bind --task cvg/tasks/T-20260815-health-status.md
cvg bind --check --task cvg/tasks/T-20260815-health-status.md
git add cvg/tasks cvg/execution
git commit -m "authorize and bind health status task"
cvg loop --issue T-20260815-health-status --agent codex

Why the commit sits between bind and loop

The loop runs in an isolated worktree that sees committed state only. The sealed task and execution profile must be committed first — that commit authorizes nothing beyond visibility; it is not a product merge and opens no PR.

Spend nothing to preview

Use cvg loop --estimate --issue … and cvg loop --gate-only --issue … to inspect budgets and gate state without spending a live model budget. External writes default to deny:

policy:
  external_writes: deny
capabilities:
  grants: []
budgets:
  iterations: 15
  wall_seconds: 5400
  tokens: 120000
isolation: worktree
Settlement check. After the loop lands, confirm the landing token first: LOCAL_SETTLED/SETTLED/NO_OP exit 0. Then verify Task-Spec returned ACCEPTED=1 for the exact handoff and revision before calling anything done.

Sources: brf-converge.md §8 (authorize/bind/run, default-deny policy); underlying docs/guides/bind-and-loop.md, skills/task-loop/.

Field guide · recovery and diagnosis

Recovery follows tokens, not optimism

Compose status emits one NEXT=. Loop landings preserve the handoff and work a human needs. Branch on the token, exit code, changed, and dry_run — never convert BLOCKED/STALLED/EXHAUSTED into success.

Observed stateSafe next action
Stale reviewPrepare and review again against current bytes
Interrupted materializeRerun idempotently; an exact rerun is byte-identical
EXHAUSTEDRaise the signed budget or split the task — a human decision
REFUTED (tier 2)Fix the work; do not argue the judge down
CANCELLEDResume from the written handoff
Resume limitation. Under worktree isolation, current --resume starts a fresh tree at attempt 1. Do not imply continuation of uncommitted work.

Doctors name the broken hop

Host, evidence, plugin, runtime-contract, and setup checks turn distant symptoms into one actionable upstream cause: missing shellcheck → gate blocked → unsigned task → bind refused → loop error, with the doctor pointing at the first cause. Tokens: DOCTOR_HOST, DOCTOR_EVIDENCE, DOCTOR_PLUGIN, plus the runtime-contract result.

Install without embedding engines

install.sh copy-mode pins 11 skills and the CLI into Codex/Kimi, Claude Code, and Grok destinations; Task-Spec and Seamwise remain external. Local config is 0600, symlink-safe, idempotent, and Git-excluded (17 install + 21 clean-room checks green).

Sources: brf-converge.md §5 S64–S66, S69, §8 (recovery by token); underlying docs/guides/recovery.md, install.sh, doctor scripts.
