Why “System”, not “Agent”. An agent is one loop instance (layers 1–4). What gets built is the system: orchestrator + harness + referee + method. The referee is what makes it autonomous.
02

The five layers — who thinks, who acts, who judges

Layers 1–4 are industry-standard. Layer 5 is the one most teams skip — and it is the entire trust story.

L1MODELA pure text function. Tokens in, tokens out. Stateless. No hands, no shell, no memory between calls.
L2HARNESSA normal program. Owns the API key, the while-loop, conversation state, permissions, sandboxing.
L3TOOLSBash, file edit, MCP — schemas offered to the model as text in every prompt.
L4ENVIRONMENTFilesystem, git, databases, the referee CLI — what the tools act on.
L5REFEREEGates and evals. Deterministic code. Exit 0/1 decides. The model’s opinion is never consulted.
03

The Agentic Loop — the hop map

The while-loop is not a hop — it wraps hops 1–4. The model never invokes anything. It asks. The harness calls.

Hop 0 TRIGGER chat, or a scheduler Hop 1 HARNESS ASSEMBLES one prompt: system + schemas + files + transcript Hop 2 MODEL EMITS plain text, or a request blob ← the while-loop Hop 3 HARNESS EXECUTES permission, subprocess, capture stdout / exit Hop 4 RESULT → TRANSCRIPT, back to Hop 1 until Hop 2 is plain text Hop 5 REFEREE JUDGES exit 0 / 1, outside the loop
Agent = model + while-loop + tools. Safety lives at hop 2/3: sandboxing, permission, logging — possible only because the model cannot act directly.
04

Receipt — a whole agent in forty lines

The model is scripted so only the machinery is visible. Swap the fake model for an HTTPS call and this is any coding harness, minus polish.

the hop, namedUSER : What is the paid revenue in the fixture? MODEL EMITS : {"command": "sqlite3 … SUM(paid_amount) …"} HARNESS RAN IT: exit 0 | output: 240.00 AGENT (final) : The paid revenue in the fixture is 240.00.
Read the middle line again. The model produced a JSON blob — that is all a model can ever do. A subprocess ran the command. Edit the fake model to emit a wrong command and the harness will dutifully run it. That is why Layer 5 exists.
05

How the model “knows” the tools

Nobody wires the model to a CLI. Three mechanisms — all just text in the window. Remove the words, the knowledge vanishes.

Tool schemas

  • Injected into every request
  • “Bash takes {command}”
  • The model was trained to emit a well-formed call when the task needs one

Ambient docs

  • AGENTS.md, skills, pass names
  • The context window is the model’s only interface to your world

Runtime discovery

  • It explores like a human: ls, then help
  • Discovery uses the same loop
06

Two seats of the referee CLI

The same binary occupies two completely different positions relative to the loop.

Seat A · inside

A tool the model asks for

During hops 2–3 the model emits a command; the harness runs it. The referee is just another program in the environment.

Seat B · outside

Launcher + referee

Pre-gate the work → spawn an entire agentic loop as one subprocess → ignore its self-report → run the referee → done, retry, or park.

the nesting you / a scheduler ← trigger └─ orchestrator ← picks ready work └─ work T-1 --engine … ← Seat B ├─ pre-gate ├─ spawn ▶ THE LOOP (hops 1–4) │ └─ may call the CLI again (Seat A, nested) ├─ post-gate: referee re-runs evals — 0/1 └─ done / retry / park
07

The launcher never believes the thinker

Seat B in one beat: the loop self-reports; the launcher ignores it and checks the world.

launcherloop finished. Its SELF-REPORT was: AGENT (final) : The paid revenue in the fixture is 240.00. REFEREE runs independently (ignore the self-report): SMOKE: PASS · paid revenue = 240.00 verdict: VERIFIED → work would move to done
One sentence: spawn the thinker, never believe it, check the world. If verification only happens inside the loop, the transcript can claim anything.
08

What working professionals get wrong

BeliefReality
“The model runs commands”The harness runs them. The model emits a request blob.
“The model remembers our conversation”The transcript is re-sent in full on every call.
“The model knows my tools”Schemas are injected every time. Remove them, knowledge gone.
“An agent is a special model”Agent = same model + while-loop + tools.
“MCP is a protocol models speak”MCP is harness plumbing. The model just sees more schemas.
“Autonomy means a smarter model”Autonomy = a scheduler replaces the trigger, a referee replaces judgment.
09

ASD — how you build the machine

Opposite of what most teams do: validate the method before wrapping it, harden on a fixture, remove the human last — one gate at a time.

Phase 0

Foundations

before any model touches anything
  • Name the anatomy — own the referee and the method, rent the models
  • Write the contract file (one file = the law)
  • Build a test floor with designed failures
  • Stage a proving ground for the method
Phase 1

Method validation

five beats per pass
  • Understand — audit the skill against the field
  • Run — for real, human judging
  • Canonize — skill = blueprint; gate goes green
  • Implement — thin CLI: frame → dispatch → collect → gate
  • Prove — CLI re-run must match the manual golden run
Phase 2

Machine hardening

fixture only
  • CI re-runs every eval in a clean container
  • One worker; parks, never spins
  • A stateless manager: locks, worktrees
  • Board + event ledger
  • Cross-engine judge, injection defense
Phase 3

Autonomy graduation

remove yourself one gate at a time
  • A scheduler replaces the human trigger
  • Humans remain only where blast radius demands
  • Receipts pick the engine
  • Re-run evals on a schedule; drift reopens work
10

Six invariants — the actual doctrine

The phases are construction order. These six hold in every phase.

1eval defines doneNever the model’s claim, never a feeling — exit 0 from a sealed check.
2evals discriminateAnything that passes before the work exists is a broken check.
3state lives outsideFiles, git, tracker. “Memory” is re-injected text.
4one writer per stateThe CLI writes, the board renders, the model asks.
5automate triggersJudgment gets gates. Only the trigger gets a scheduler.
6own every layerA harness you cannot explain is a harness you cannot trust.

12

Does Converge match this logic?

Yes — on the product method row. Converge is not a second anatomy. It is the descent that runs on this anatomy. ASD is how you build the referee so Converge can run unattended.

Eval defines done

Converge: “converged means an eval passed, not that you feel done.” Same invariant.

match
Every pass ends at a gate

Converge’s eight passes each lower altitude and stop at a gate. Pass 8 does not lower — it closes. That is Hop 5, productized.

match
Two seats

A pass skill asked from inside the loop is Seat A. cvg launching a worker and ignoring its self-report is Seat B.

match
Task-Spec as unit

Pass 5 is the six-tier Task-Spec engine. The eval travels inside the task. That is “no eval, no task.”

match
Factory from day one

Converge refuses the retrofit: gates exist from Pass 1, so walking out later does not require a rewrite. That is ASD Phase 0–3, compressed into the spine.

match
Not the same object

Converge does not replace L1–L5. It assumes them. ASD Phases 0–3 are how you construct cvg; the eight passes are what that machine then executes. Blur those and the room thinks Converge “is” the loop.
