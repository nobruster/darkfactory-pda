The five layers — and who is allowed to decide

Only two things ever cross between them: text and exit codes. Nothing else.

L1 Model A pure text function: tokens in, tokens out. Stateless. No hands, no shell, no memory between calls. Rented, and interchangeable.
L2 Harness A completely normal program. It owns the API key, the while-loop, the conversation state, the permissions, the sandbox. Owned, and where your differentiation lives.
L3 Tools Shell, file edits, MCP servers — functions the harness offers the model as text descriptions, in every single prompt. Every tool you add is a tax on the context window.
L4 Environment Filesystem, git, databases, the command-line tools of your project. What the tools actually act on — tonight, a payments legacy nobody dares touch.
L5 Referee Deterministic gates and evals. Exit 0 or exit 1 decides. The model's opinion is never consulted — it is not even asked.
the layer nobody builds
Layers 1–4 are industry standard — you already have all four. Layer 5 is the one most teams skip, and it is the entire trust story.
the sentence the whole field converged on
Agent = Model + Harness. If you are not the model — and you are not — then you are the harness. That is the job.
one turn of the loop, hop by hop

The model never invokes anything

hop 0
CHAT — or a scheduler. anything that starts a turn.
hop 1
HARNESS ASSEMBLES one big text prompt:
system prompt + tool schemas + project docs + the ENTIRE conversation so far + your message
hop 2
MODEL EMITS plain text — or a request blob:
{"name":"bash","input":{"command":"make df-accept"}}
hop 3
HARNESS EXECUTES — permission check, subprocess,
capture stdout / stderr / exit code
hop 4
RESULT → TRANSCRIPT, go back to hop 1
the while-loop wraps hops 1–4 and repeats until hop 2 comes back as plain text
hop 5
REFEREE JUDGES the outcome — exit 0 / 1 — outside the loop, and it never reads the transcript
the sentence to take home
The model asks — at hop 2. The harness calls — at hop 3. A model has never run a command in its life.
and why that gap matters
Every piece of safety lives in the space between hop 2 and hop 3: permissions, sandboxing, logging. They are possible only because the model cannot act directly.

rung 2, up close — because a four-hour run is a context problem before it is anything else

Attention is a budget, and it is spent whether you plan it or not

the constraint
A finite attention budget

Every token you add competes with every other token. A million-token window is not a million tokens of attention — it is a million tokens of room.

the failure mode
Context rot

Measured across 18 frontier models: output quality degrades as input grows — and it starts degrading well before the window is full. Filling the window is not using it.

the goal
Smallest high-signal set

Not “give it everything.” Find the smallest set of tokens that maximizes the chance of the outcome you want. Everything below is a way to spend less and get more.

lever 1
Just-in-time retrieval

Keep the window full of pointers, not payloads — file paths, saved queries, skill names. Load the heavy thing at the moment it is needed, then let it go. The agent explores instead of being pre-loaded.

lever 2
Compaction

When the window nears its limit, summarize it faithfully and start a fresh one from the summary. This is what lets a run survive hours instead of minutes.

lever 3
Notes on disk

Structured note-taking: plans, to-dos, decisions and journals written outside the window. This is what “memory” actually is — a file the harness chooses to re-inject.

lever 4
Sub-agent isolation

One orchestrator plans; sub-agents each work in their own window and return a condensed answer. The dirty exploration never pollutes the clean plan.

rung 3, up close — the part you own, and the only part you can defend

The model got commoditized. The harness did not.

Six things sit between a stateless text function and a machine that finishes work. None of them is a model. All of them are code you write.

01 · instructions
Prompts and project docs

System prompt, CLAUDE.md, AGENTS.md, skill files, sub-agent prompts. Delete them and the agent forgets your entire world.

02 · capability
Tools, skills, MCP servers

What the agent may call, and the descriptions that teach it how. Each one is text in every prompt — capability you pay for by the token.

03 · containment
Sandbox and permissions

Filesystem, worktree, container, network policy, approval prompts. The blast radius is a design decision — yours, not the model's.

04 · orchestration
Routing and sub-agents

Who spawns whom, which model gets which job, how work is handed off. A reviewer from a different vendor than the writer — the structural fix for a model agreeing with itself.

05 · verification
Gates and recovery

Checks that run on the output regardless of what the agent claims — plus what happens when they fail. A harness whose only completion signal is “done” has no verification layer. It has a suggestion box.

06 · observability
Traces, cost, evidence

Logs, traces, token and latency metering, and the artefacts a run leaves behind. In Act 3 this is the only reason you will believe anything.

MCP, placed correctly
MCP is harness-to-server plumbing — Tools, Resources and Prompts over a wire. The model never “speaks” it; it just sees more tool descriptions. Anthropic opened it in Nov 2024 and handed it to the Linux Foundation in Dec 2025. It is infrastructure now, not a vendor feature.
the receipt from the other side of the industry
OpenAI, writing about running Codex on their own product: early progress was slow “not because Codex was incapable, but because the environment was underspecified.” When the agent struggles, that is a bug in the harness — so they fix the harness.

six things working professionals get wrong every day

What you believe × what is running

01the harness runs it
“The model runs commands.”
The harness runs them. The model emits a request and waits, exactly like the demo you just read.
02nothing is remembered
“The model remembers our conversation.”
The transcript is re-sent in full on every call. “Memory” is text someone chose to re-inject — a file, a note, a summary.
03schemas, every prompt
“The model knows my tools.”
Tool schemas are injected into every prompt. Delete the words and the knowledge is gone that same second.
04the wrapper is the agent
“An agent is a special kind of model.”
Agent = the same model + a while-loop + tools. You rent the model. You build the rest.
05plumbing, not language
“MCP is a protocol that models speak.”
MCP is harness-to-server plumbing — Tools, Resources, Prompts. The model just sees more tool schemas. And it belongs to the Linux Foundation now, not to a vendor.
06trigger and judgment
“Autonomy means a smarter model.”
Autonomy = a scheduler replaces the human trigger, and a referee replaces human judgment. Neither one is a model.Which is why the last item on that list is the expensive one.

four authorities that must never be merged — the single most important slide in this act

“Correct” is four different questions

01 · system of record
What was declared

The upstream owns the raw file and the totals it declares. Committed database tables own the applied state. Declared is not the same as correct — and this system is not allowed to quietly improve it.

02 · source of observation
What actually happened

Bytes, hashes, manifests, database readings, terminal status, evidence packets. Neutral by construction. It records the run without judging it.

03 · source of correctness
What should have happened

Independently reviewed expected output, expected reconciliation, governed business rules. Written by a human who was not the implementer, and never edited to make a run pass.

04 · executable contract
What was agreed, in Git

Versioned YAML, schemas, canonical fixtures, tests. Not a document about the rules — the rules, in a form a machine can fail against. Change control is a decision record, not a commit.

When a source declares one thing and three implementations compute another, the system keeps the wrong declaration exactly as written and preserves the disagreement as evidence. It does not average them. It does not pick a winner. It refuses to merge the roles — and that is why, later tonight, we will be able to say who was wrong.
the risk that actually kills you

The real risk is not the system going down. It is the system working — and being wrong.

An outage pages someone in four minutes. One swapped offset, one inverted sign, one rounding mode — that ships green, reconciles against itself, and gets found by an auditor a quarter later.

an outage
Loud. Immediate. Someone is already awake and fixing it. Cost: hours.
a plausible-wrong number
Silent. Passes every test that exists. Lands in a report someone trusts. Cost: a quarter, plus your credibility.
why tests miss it
A test written from the same misunderstanding as the code agrees with the code. Green means consistent, not correct.

the design secret

The legacy, with all its defects, is the oracle.

what an oracle is

what an oracle is not
Correct. An oracle is evidence, not truth. It can be wrong, and when it is, the disagreement is the finding — not something to paper over.

why not trust the tests
Tests written from the same reading of the spec as the code will pass on the same misunderstanding. You need a second implementation — not a second reading of the first one.
what this buys you
Every disagreement is now cheap to find and expensive to ignore — which is exactly the trade you want when the unit of truth is a cent.

the assembly line that took one file type from a specification to deployed production data

Eight gates. And exactly one human decision.

stall, never halt
One type's failure stalls that type, with the exact stage and reason recorded — and the queue carries on. The operator cadence is a morning review: the loop works the queue overnight, and a stall is not urgent until breakfast.
the honest answer to “is it really unattended?”
No — and that is the design. Eight stages run with nobody watching. Cloud deployment is a human decision, written down as a rule, because that is the boundary where a mistake stops being reversible.

the single most dangerous move in the entire programme
“Edit the parser until the diff goes away.” It always works, it is always available, and it destroys the evidence that anything was ever wrong. So every dirty column gets classified before anyone is allowed to touch code.
branch 01
Representation

Naming, datetime, decimals, padding. The values agree; the shapes do not. A configuration edit only — never a parser change.

branch 02
Fixture defect

The golden side is wrong. Exclude it with a cited exception — never by quietly bending the parser to match a bad reference.

branch 03
Legacy manufacture

The old system invented a value — an empty string silently becoming zero. The procedure decides whether the new one inherits the quirk or stays faithful.

branch 04
Parser bug

The only branch allowed to edit code — and only with a citation to a procedure, a schema, or a raw byte. No citation, no edit: stall with proof.

Sixty lessons became five skills and three gates

a lesson earns a callable skill when all three hold: 1. recurrence cited across ≥ 3 types 2. high cost financial · data-corruption · cloud-failure class 3. mechanizable a deterministic decision tree — not a judgement call the loop creates the skill itself. it does not defer to a human.
and then it proves the promotion
The lesson is retired into a pointer — “now enforced by the skill” — and one existing caller is retrofitted as proof that the skill produces identical output with less code. A promotion that is not demonstrated is not a promotion.

No check, no dispatch
